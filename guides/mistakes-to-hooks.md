# Повторювані помилки AI → хуки Claude Code

Проблема: ти пишеш правило в `CLAUDE.md` або в пам'ять, агент його знає і все одно порушує. Пам'ять не спрацьовує
в момент дії, а хук спрацьовує. Нижче наш спосіб переводити помилки з «пам'яті» в «хук».

## Правило переходу

1. Помилка повторилась **удруге**, хоч правило вже є в пам'яті → записуєш її в таблицю.
2. Якщо її можна впізнати машинно (текст команди, рядок у файлі) → пишеш хук (`PreToolUse` для команд і правок,
   `Stop` для відповіді в чаті) і тест: хук **ловить відоме порушення і пропускає чистий випадок**.
3. Якщо машинно не впізнати (тон, вибір слова) → лишається пам'ять, у таблиці позначка «лише пам'ять».
4. Раз на місяць дивишся журнал спрацювань: хук, який ні разу не спрацював, або зайвий, або сліпий.

## Наша таблиця (приклад)

| Помилка | Скільки разів до хука | Що ловить | Режим |
|---|---|---|---|
| Довге тире в текстах для відправки | регулярно | хук на нові рядки-цитати у файлах + на останнє повідомлення в чаті | блок у файлі, прохання в чаті |
| `Co-Authored-By: Claude` у коміті | 3 | хук на `git commit` + `attribution: ""` у `~/.claude/settings.json` | блок |
| Push, коли локальна гілка позаду remote | 1 раз ледь не затер файл | хук: `git fetch` і рахунок комітів позаду | блок |
| Force-push без `--force-with-lease` | ризик для паралельної сесії | хук на `push --force` | питає людину |
| Правка n8n напряму в БД (`UPDATE workflow_entity`) без `workflow_history` | 2, одна ховалась 2 тижні | хук на текст SQL | блок |
| Код з `\n` через heredoc | 2 за день, прод лежав 7 год | хук на heredoc з escape | попередження |
| Читання величезного файлу цілком | системно | `PreToolUse` на `Read` без `offset`/`limit` для файлів > 100 КБ | блок |
| «Все добре» без перевірки, що замір бачить погане | 3 за сесію | не впізнати машинно | лише пам'ять |

## Що варто знати наперед

- **Вимикачі.** Кожен хук перевіряє файл-прапорець (наприклад, `~/.claude/bash-guard-off`): файл є = хук вимкнено,
  рестарт не потрібен. Без цього зламаний хук заблокує тобі роботу посеред ночі.
- **Fail-open.** Збій скрипта хука = дозвіл. Робота не зупиняється через баг у запобіжнику.
- **Хук читає текст команди.** SQL, який лежить у файлі на сервері (`psql < f.sql`), він не побачить.
- **Шукати підрядок = хибні спрацювання.** Наш перший хук блокував навіть `echo "... Co-Authored-By"`.
  Звузили до виклику `git commit` на початку команди і додали цей випадок у тест.
